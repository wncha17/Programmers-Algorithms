## 📝 [Hash] 완주하지 못한 선수 (Lv. 1)
> **문제 링크:** [https://school.programmers.co.kr/learn/courses/30/lessons/42576]

### 1. 🔍 Key Signal (문제의 단서)
- **키워드:** "단 한 명의 선수를 제외하고는 모든 선수가 완주", "이름이 담긴 배열", "중복 가능성(동명이인)"
- **알고리즘:** 해시(Hash)
- **판단 근거:**
  1. 참가자(participant)와 완주자(completion)의 길이는 최대 100,000이다.
  2. 이중 루프(O(N^2))로 비교하면 100억 번의 연산이 필요해 시간 초과가 발생한다.
  3. 이름(문자열)을 키(Key)로 삼아 빠르게(O(1)) 데이터를 찾고 개수를 세어야 하므로 해시가 최적이다.

### 2. 💡 Strategy (설계)
1. 빈 해시 테이블(딕셔너리)을 생성한다.
2. participant를 순회하며 {이름: 인원수} 형태로 저장한다. (동명이인은 +1)
3. completion을 순회하며 해시 테이블에서 해당 이름의 인원수를 -1씩 뺀다.
4. 마지막에 인원수가 0이 아닌(1인) 이름을 찾아서 반환한다.

### 3. ⚠️ Edge Case & Pitfalls
- **동명이인**: 단순히 set을 써서 차집합을 구하면 동명이인 처리가 안 된다. (예: 'mislav'가 2명인데 1명만 완주한 경우)
- **효율성**: Python의 dict는 내부적으로 해시 테이블로 구현되어 있어 매우 빠르다. 더 세련된 풀이를 원한다면 collections.Counter 활용 가능.

### 4. 🛠️ Implementation (코드 요약)
- **[Solution 1]: Hash Dictionary 활용 (정석적 접근)**
  - 로직: 딕셔너리에 참가자 수를 카운트하고, 완주자를 뺄셈하여 남는 자를 찾음.
  - 특징: 가장 범용적이며, 해시의 원리(O(1) 탐색)를 가장 잘 보여줌.

- **[Solution 2]: Python collections.Counter 활용 (언어 특화)**
  - 로직: 객체 간의 뺄셈 연산 기능을 활용하여 한 줄로 해결.
  - 특징: 가독성이 뛰어나고 구현 속도가 빠름. 실무 생산성 강조 시 유리.

- **[Solution 3]: Sorting 활용 (메모리 효율적 접근)**
  - 로직: 두 배열을 정렬한 뒤, 인덱스 별로 비교하다가 값이 다른 지점의 참가자가 정답.
  - 특징: 해시 테이블을 위한 추가 메모리 할당이 적음. 해시 충돌 위험이 없는 환경에서 고려할 만함.

### 5. 🏟️ Real-world Connection
- **데이터 정합성 검증**: 대규모 결제 트랜잭션이나 차량 데이터 수신 리스트 대조 시, 누락된 데이터(Missing Data)를 O(N)의 속도로 빠르게 식별하여 시스템 신뢰성을 보장함.

## 📝 [Hash] 폰켓몬 (Lv. 1)
> **문제 링크:** [https://school.programmers.co.kr/learn/courses/30/lessons/1845]

### 1. 🔍 Key Signal (문제의 단서)
- **키워드:** "N/2마리 선택", "가장 많은 종류의 폰켓몬", "중복된 번호는 같은 종류"
- **알고리즘:** Hash (Set)
- **판단 근거:**
  1. 선택할 수 있는 최대 마리수는 정해져 있다.
  2. 우리가 관심 있는 건 '마리수'가 아니라 '종류의 수'이다.
  3. 종류를 파악하기 위해 중복을 제거하는 가장 빠른 방법은 해시 기반의 set 자료구조를 사용하는 것이다.

### 2. 💡 Strategy (설계)
- **[Solution 1] set을 활용한 중복 제거 (가장 직관적)**
  - 로직: 폰켓몬 리스트를 set으로 변환하여 고유한 종류의 수를 구하고, 이를 N/2와 비교함.
  - 특징: 코드 한 줄로 해결 가능하며, 해시 셋의 시간 복잡도(O(N))를 활용함.

- **[Solution 2] dict를 활용한 카운팅 (확장성 고려)**
  - 로직: 딕셔너리에 각 폰켓몬의 종류별 마리수를 저장한 뒤, 딕셔너리 키의 개수를 확인함.
  - 특징: 만약 문제에서 "특정 종류의 폰켓몬을 몇 마리 가졌는지도 출력하라"는 요구사항이 추가될 경우 대응하기 좋음.

### 3. ⚠️ Edge Case & Pitfalls
- **과도한 최적화의 함정**: N/2보다 종류가 많을 때, 어떤 폰켓몬을 골라야 하는지 고민할 필요가 없다. "최대 종류의 수"만 물었으므로 단순 비교(min)로 끝내야 한다.

### 5. 🏟️ Real-world Connection
- **Unique Visitor/Device 카운팅**: 현대자동차 커넥티드 카 서비스인 '블루링크' 서버에서 특정 시간 동안 접속한 '고유 차량 대수'를 집계할 때 사용한다.  
  수백만 건의 접속 로그(nums)가 쌓여도 해시(Set)를 이용하면 중복을 제거하고 실제 서비스 이용 차량이 몇 대인지 O(N)의 속도로 빠르게 계산할 수 있다.

## 📝 [Hash] 전화번호 목록 (Lv. 2)
> **문제 링크:** [https://school.programmers.co.kr/learn/courses/30/lessons/42577]

### 1. 🔍 Key Signal (문제의 단서)
- **키워드:** "한 번호가 다른 번호의 접두어인 경우", "번호의 길이는 최대 20", "전체 번호 개수는 최대 1,000,000"
- **알고리즘:** Hash (Dictionary/Set) or Sorting
- **판단 근거:**
  1. 데이터가 100만 개이므로 O(N^2)의 이중 루프 비교는 절대 불가능하다.
  2. 각 번호를 잘라가며(Substring) 해시 맵에 존재하는지 확인하는 O(N * L) (L: 전화번호 길이) 방식이 필요하다.
