## 📝 [Hash] 완주하지 못한 선수 (Lv. 1)
> **문제 링크:** [https://school.programmers.co.kr/learn/courses/30/lessons/42576]

### 1. 🔍 Key Signal (문제의 단서)
- **키워드:** "단 한 명의 선수를 제외하고는 모든 선수가 완주", "이름이 담긴 배열", "중복 가능성(동명이인)"
- **알고리즘:** 해시(Hash)
- **판단 근거:**
  1. 참가자(participant)와 완주자(completion)의 길이는 최대 100,000이다.
  2. 이중 루프(O(N^2))로 비교하면 100억 번의 연산이 필요해 시간 초과가 발생한다.
  3. 이름(문자열)을 키(Key)로 삼아 빠르게(O(1)) 데이터를 찾고 개수를 세어야 하므로 해시가 최적이다.

### 2. 💡 Strategy (설계)
1. 빈 해시 테이블(딕셔너리)을 생성한다.
2. participant를 순회하며 {이름: 인원수} 형태로 저장한다. (동명이인은 +1)
3. completion을 순회하며 해시 테이블에서 해당 이름의 인원수를 -1씩 뺀다.
4. 마지막에 인원수가 0이 아닌(1인) 이름을 찾아서 반환한다.

### 3. ⚠️ Edge Case & Pitfalls
- **동명이인**: 단순히 set을 써서 차집합을 구하면 동명이인 처리가 안 된다. (예: 'mislav'가 2명인데 1명만 완주한 경우)
- **효율성**: Python의 dict는 내부적으로 해시 테이블로 구현되어 있어 매우 빠르다. 더 세련된 풀이를 원한다면 collections.Counter 활용 가능.

### 4. 🛠️ Implementation (코드 요약)
- **[Solution 1]: Hash Dictionary 활용 (정석적 접근)**
  - 로직: 딕셔너리에 참가자 수를 카운트하고, 완주자를 뺄셈하여 남는 자를 찾음.
  - 특징: 가장 범용적이며, 해시의 원리(O(1) 탐색)를 가장 잘 보여줌.

- **[Solution 2]: Python collections.Counter 활용 (언어 특화)**
  - 로직: 객체 간의 뺄셈 연산 기능을 활용하여 한 줄로 해결.
  - 특징: 가독성이 뛰어나고 구현 속도가 빠름. 실무 생산성 강조 시 유리.

- **[Solution 3]: Sorting 활용 (메모리 효율적 접근)**
  - 로직: 두 배열을 정렬한 뒤, 인덱스 별로 비교하다가 값이 다른 지점의 참가자가 정답.
  - 특징: 해시 테이블을 위한 추가 메모리 할당이 적음. 해시 충돌 위험이 없는 환경에서 고려할 만함.

### 5. 🏟️ Real-world Connection
- **데이터 정합성 검증**: 대규모 결제 트랜잭션이나 차량 데이터 수신 리스트 대조 시, 누락된 데이터(Missing Data)를 O(N)의 속도로 빠르게 식별하여 시스템 신뢰성을 보장함.
